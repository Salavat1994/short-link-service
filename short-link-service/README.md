# Short Link Service — консольный сервис сокращения ссылок

Учебный проект по ТЗ PROMO IT: сокращение URL, уникальные коды, UUID-владельцы,
ограничение переходов, автоматическое удаление по TTL, уведомления и CLI.

**Технологии:** Java 17+, Maven 3.9+, JUnit 5. Без Spring Boot, БД и стороннего HTTP-сервера:
по заданию приложение работает **в консоли**. `Desktop.browse(...)` открывает исходную
страницу браузером компьютера.

> Важно: `short.local/XXXXXXXX` — учебное обозначение короткой ссылки **внутри CLI**.
> Это не зарегистрированный домен и не публичный URL. В браузере вводится **исходный**
> адрес после выполнения команды `go` в консоли. Реальный сайт/редирект-сервер не входят в ТЗ.

## 1. Быстрый запуск в IntelliJ IDEA

1. Распакуйте проект и откройте папку, **где находится `pom.xml`**, через *File → Open*.
2. Откройте Project Structure → Project и выберите **JDK 17 или 21**.
3. Дождитесь импорта Maven-зависимостей.
4. Откройте `src/main/java/ru/homework/shortlinks/ShortLinkApplication.java`.
5. Нажмите **Run ▶** рядом с `main`. Приложение ждёт команды в окне Run.
6. Введите `help`, затем `create https://www.baeldung.com/java-9-http-client 2`.

В IntelliJ IDEA для ввода команд иногда удобнее открыть отдельный Terminal и выполнить:

```bash
mvn clean package
java -jar target/short-link-service-1.0.0.jar
```

Для Windows PowerShell команды такие же. **Аргументы при запуске не нужны.**

## 2. Пользовательские команды

| Команда | Описание |
|---|---|
| `help` | Полный список команд |
| `create <URL> [лимит]` | Создать короткую ссылку. Лимит необязателен |
| `go <код или short.local/код>` | Открыть исходный URL в браузере |
| `short.local/код` | Можно просто вставить короткий адрес без команды `go` |
| `list` | Показать только свои активные ссылки |
| `info <код>` | Параметры своей ссылки |
| `set-limit <код> <лимит>` | Изменить лимит своей ссылки |
| `set-url <код> <URL>` | Изменить адрес своей ссылки |
| `delete <код>` | Удалить свою ссылку |
| `whoami` | Показать UUID активного пользователя |
| `user-new` | Начать сессию нового пользователя (UUID будет при следующем `create`) |
| `user-use <UUID>` | Вернуться к существующему пользователю по его UUID |
| `notifications` | Показать и отметить прочитанными уведомления текущего пользователя |
| `exit` | Завершить приложение |

URL пишите без пробелов, с `http://` или `https://`. Команды нечувствительны к регистру
только в имени (`CREATE`/`create`), значения URL и кодов не меняются.

### Сценарий: создание, переход и блокировка

```text
shortlinks> create https://www.baeldung.com/java-9-http-client 2
Создан UUID пользователя: <новый UUID>
Короткая ссылка: short.local/XXXXXXXX
Доступно переходов: 2
Действует до: <время UTC>

shortlinks> go short.local/XXXXXXXX
Открыт исходный адрес в браузере. Переходов: 1/2

shortlinks> go XXXXXXXX
Открыт исходный адрес в браузере. Переходов: 2/2
Уведомление: лимит достигнут, дальнейшие переходы заблокированы.

shortlinks> go XXXXXXXX
Ошибка: Лимит переходов исчерпан. Ссылка недоступна; создайте новую.

shortlinks> notifications
[<время>] short.local/XXXXXXXX: исчерпан лимит переходов. Можно создать новую ссылку.
```

Вместо `XXXXXXXX` приложение сгенерирует случайный 8-символьный код. UUID — также случайный.
**Первый `create` создаёт UUID**, следующие `create` этой сессии используют его.

### Сценарий: несколько пользователей и изоляция

1. Создайте ссылку `create https://example.org 3` и скопируйте UUID и код **А**.
2. Введите `user-new`, затем создайте точно такой же URL и сохраните UUID и код **Б**.
3. Коды будут различаться; `list` покажет только ссылку Б.
4. Попробуйте `delete <код А>` — программа откажет: это ссылка другого пользователя.
5. Введите `user-use <UUID А>` и `list` — снова увидите ссылку А.
6. `set-limit <код А> 5` теперь сработает.

**Модель владения:** UUID — предъявляемый идентификатор пользователя (*bearer token*).
По условию задания **авторизации нет**. Поэтому владение UUID означает право выбрать
соответствующего пользователя; не передавайте чужим UUID. Это не система защищённой
аутентификации и не предназначено для настоящего публичного сервиса.

### Сценарий: проверка TTL

1. Остановите приложение.
2. В `config/application.properties` задайте `link.ttl.seconds=10` и
   `link.cleanup.seconds=1`.
3. Запустите программу, выполните `create https://example.org 2`.
4. Через ~10 секунд плюс до одного интервала очистки ссылка автоматически удалится,
   даже если команду `go` никто не вводит. В консоли появится сообщение об очистке.
5. `list` больше не содержит ссылку; `notifications` содержит сообщение об истечении TTL.
6. Верните `link.ttl.seconds=86400` и `link.cleanup.seconds=5` для обычной работы.

Если приложение закрыто в момент истечения TTL, очистка запускается **сразу при
следующем старте**. Также срок проверяется перед каждым запросом к ссылке.
TTL назначается системой и не изменяется пользователем через CLI.

## 3. Конфигурация

Файл: `config/application.properties`. При обычном запуске из корня проекта его значения
имеют приоритет над встроенными `src/main/resources/application.properties`. Если
внешний файл отсутствует, используются встроенные параметры.

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `link.ttl.seconds` | `86400` | Время жизни ссылки (24 часа) |
| `link.clicks.default` | `5` | Лимит переходов при пропуске аргумента |
| `link.clicks.max` | `1000` | Наибольший разрешённый лимит |
| `link.cleanup.seconds` | `5` | Интервал фоновой очистки, секунды |
| `link.prefix` | `short.local/` | Префикс отображаемой короткой ссылки |
| `link.storage.path` | `data/shortlinks.properties` | Файл долговременного хранения |

Чтобы изменить конфигурацию, отредактируйте файл и **перезапустите** приложение.
Время в `expiresAt` и уведомлениях отображается в UTC, точность отсчёта TTL — секунды.

Данные сохраняются в `data/shortlinks.properties`: UUID, ссылки, счётчики, время
истечения и ожидающие уведомления. **Удаление `data/` удаляет всю историю.** Папка
исключена из Git через `.gitignore`, чтобы случайно не публиковать пользовательские UUID.
Запускайте **один экземпляр приложения на одну папку данных**: межпроцессная блокировка
не нужна для данного консольного ТЗ и не реализована.

## 4. Как это устроено

```text
ConsoleUi (команды, сообщения)
    |                    \
    v                     \-> DesktopBrowser -> системный браузер
LinkService (права, лимиты, TTL, UUID, события)
    |         ^
    |         |
    |     ScheduledExecutorService (периодическая очистка)
    v
LinkStore (контракт хранения)
    v
PropertiesLinkStore -> data/shortlinks.properties
```

- `config/AppConfig` — чтение и проверка TTL, лимитов, интервала очистки, пути данных.
- `core/ShortLink`, `Notice`, `State` — неизменяемые модели.
- `core/UrlValidator` — разрешены только абсолютные HTTP(S)-адреса с доменом;
  запрещены userinfo, управляющие символы и URL длиннее 2048 символов.
- `core/SecureCodeGenerator` — 8 случайных символов Base62 (`SecureRandom`);
  `LinkService` проверяет уникальность по всем ссылкам и повторяет генерацию при коллизии.
- `core/LinkService` — бизнес-правила и ограничение прав владельца.
- `infra/PropertiesLinkStore` — запись нового файла и атомарная замена старого;
  повреждённое состояние приводит к ошибке, а не к молчаливому сбросу.
- `infra/DesktopBrowser` — вызов стандартного Java `Desktop.browse`.
- `ui/ConsoleUi` — работа с пользователем без бизнес-логики.

### Точность переходов

Счётчик и проверка лимита синхронизированы; в одном процессе даже одновременные
попытки не могут превысить заданный лимит. **Разрешённая попытка засчитывается и
сохраняется до вызова браузера**, иначе при падении программы можно было бы обойти
лимит. Если браузер отсутствует (например, headless-среда), консоль объясняет,
что попытка учтена. Отклонённые попытки счётчик не увеличивают.

### Уведомления

При последнем разрешённом переходе консоль сразу сообщает о блокировке,
а владельцу создаётся персональное уведомление. При наступлении TTL фоновый
планировщик удаляет ссылку, выводит сообщение об очистке и сохраняет персональное
уведомление. Владелец видит его через `notifications` (или после следующего старта
приложения). Уведомление после просмотра удаляется из очереди. Другие пользователи
не могут читать эту очередь.

## 5. Тестирование

```bash
mvn clean test
mvn clean verify
mvn spotless:check
```

Содержится **42 теста JUnit 5**:
проверяются создание UUID, многопользовательский режим, одинаковые URL, уникальные
коды, ограничения прав, изменение URL и лимита, лимит при конкурентных переходах,
очистка по TTL (с управляемыми часами, без ожидания реального часа), уведомления,
валидация, сохранение после перезапуска и CLI.

`mvn clean verify` выполняет компиляцию, тесты и Spotless-проверку пробелов/концов строк.
В `.github/workflows/ci.yml` на `push`/`pull_request` запускается GitHub Actions
с JDK 17 и `mvn clean verify`.

### Проверка вручную

- `create` с одинаковым URL под разными UUID → **разные** коды.
- 2 разрешённых `go` при лимите 2 → третий заблокирован.
- `set-limit` увеличивает лимит без сброса уже использованных переходов.
- `delete` и `set-url` под другим UUID → запрет.
- TTL=10 и cleanup=1 → запись удалена по времени, уведомление сохранено.
- Закройте приложение и запустите снова → ссылки, счётчики и UUID сохранились.

**Внимание:** автоматический запуск реального браузера в тестах не требуется:
CLI-тесты подставляют тестовую реализацию `BrowserLauncher`, поэтому тесты
работают и на GitHub Actions без графического интерфейса.
